PROPOSAL 03 · HIGH RISK, HIGH REWARD

Predictive Latent Filtering

고정 크기의 causal visual state가 미래 latent distribution을 예측하고, 실제 관측이 도착하면 uncertainty로 보정된 semantic innovation을 이용해 memory update와 recurrent computation을 함께 할당한다.

PRIMARY AXISPredict · correct
RESOURCEFixed state budget
MAIN METRICAccuracy–FLOPs Pareto
ONE-SENTENCE CLAIM

uncertainty-calibrated predictive innovation으로 state write와 recurrent depth를 공동 제어하면, 고정 memory에서도 긴 video의 anticipation과 temporal representation을 효율적으로 개선할 수 있다.

01 · THE PROBLEM

모든 prediction error가 기억하거나 더 생각할 가치가 있는 것은 아니다.

camera shake와 본질적으로 불확실한 motion은 error가 커도 semantic change가 아닐 수 있다. 반대로 짧은 object-state change는 작게 보여도 미래 action을 뒤집는다. raw error가 아니라 uncertainty로 정규화한 semantic innovation이 state update와 추가 compute를 결정해야 한다.

BELIEF REVISION SCENE

초기 관측은 A를 지지하지만, 늦게 들어온 짧은 증거가 결론을 B로 뒤집는다.

좋은 state는 과거를 더 저장하는 데서 멈추지 않고 “내 예측이 틀렸다”는 신호로 내부 belief를 수정해야 한다.

L1

Prediction alone is already established

latent future prediction 자체는 RSSM·Dreamer·V-JEPA 계열이 이미 강하게 보여줬다. streaming encoder에서 무엇을 새로 제어하는지가 필요하다.

L2

Memory update ≠ iterative reasoning

frame을 compression·retrieval하는 것만으로는 동일 state 위에서 여러 번 inference하는 test-time compute가 생기지 않는다.

L3

Raw surprise wastes resources

예측 불가능하지만 중요하지 않은 변화에 memory와 compute를 쓰면 efficient encoder claim이 무너진다.

L4

More steps can be empty computation

latent iteration이 future prediction과 downstream anticipation을 개선하지 않으면 reasoning이 아니라 weight-tied depth 반복이다.

02 · PRIOR-WORK BOUNDARY

Predict–correct 자체도 새롭지 않다. 무엇을 공동 제어하는지가 novelty다.

THE OPEN GAP

Uncertainty-calibrated predictive innovation: 고정된 causal state에서 reducible semantic prediction error가 어떤 memory slot을 수정할지와 recurrent correction을 얼마나 수행할지를 함께 결정하면, raw surprise·larger memory·fixed depth보다 나은 accuracy–compute trade-off를 만들 수 있는가?

03 · METHOD

Predict a distribution, measure semantic innovation, then spend compute only where belief must change.

slow video encoder는 새 chunk를 한 번만 읽는다. bounded posterior state에서 recurrent latent core가 기본적으로 다음 teacher latent 하나를 예측하고, 더 긴 anticipation이 유효할 때만 rollout을 연장한다. 실제 chunk가 오면 uncertainty-normalized residual을 계산하고, 높은 semantic innovation이 발생한 slot에만 recurrent corrector와 memory write를 집중한다.

Core encoder는 language query나 textual CoT를 사용하지 않는다. downstream task head는 고정된 posterior state만 읽는다.

M1

Bounded posterior state

고정된 N개 latent token이 긴 stream의 stable context와 recent event residual을 유지한다. 영상 길이가 늘어도 state 크기는 증가하지 않는다.

M2

Prospective latent reasoner

동일 recurrent core가 다음 semantic latent를 먼저 예측한다. multi-horizon은 기본 전제가 아니라 H={1,2,3,4} 실험에서 유효할 때만 adaptive rollout으로 채택한다.

M3

Innovation-gated corrector

동일 weight-tied corrector를 K번 반복하되 calibrated innovation이 update할 slot과 halting depth를 결정한다.

TRAINING OBJECTIVE

예측은 미래를 보존하고, correction은 실제 관측 뒤의 다음 예측을 더 정확하게 만들어야 한다.

hₜ¹ = Rθ(Mₜ; predict), Ẑₜ₊₁ = G(hₜ¹)
Iₜ₊₁ = d(Zₜ₊₁, Ẑₜ₊₁) / σθ(Mₜ)
Mₜ₊₁⁽ᵏ⁺¹⁾ = Rθ(Mₜ₊₁⁽ᵏ⁾, Zₜ₊₁, Iₜ₊₁; correct)
L = λpred NLL(Zₜ₊₁ | Mₜ) + λpost Lnext(Mₜ₊₁)
+ λmono Σₖ max(0, ℓₖ₊₁ − ℓₖ) + λhalt E[K] + λtask Lanticipation

06 · CONTRIBUTIONS

Query 없이도 남는 contribution은 predictive innovation을 어디에 쓰는가에 있다.

C1

Predictive streaming representation

고정 token 수의 posterior state가 multi-horizon future distribution을 보존하는 causal video encoder.

C2

Calibrated semantic innovation

raw prediction error를 uncertainty로 정규화해 nuisance motion과 task-relevant state change를 분리.

C3

Joint resource controller

하나의 innovation signal로 memory slot write와 recurrent correction depth를 공동 할당.

C4

Correction and efficiency protocol

belief revision, step scaling, bounded-memory stress를 matched FLOPs와 두 official benchmark에서 분리 검증.

07 · KILL TESTS

두 데이터셋의 정식 결과가 아래 반론을 넘지 못하면 claim을 줄인다.

NO-GO 01

RSSM이 같은 결과를 낸다

같은 state·FLOPs의 standard predictor-corrector와 차이가 없으면 새로운 video filtering mechanism claim은 성립하지 않는다.

NO-GO 02

Raw surprise가 충분하다

SPIKE·SelectStream 계열 신호가 같은 Pareto를 만들면 uncertainty calibration과 joint controller contribution을 줄인다.

NO-GO 03

추가 correction이 정보를 만들지 않는다

matched compute에서 K가 future prediction·anticipation을 개선하지 않으면 latent reasoning을 빼고 bounded predictive memory로 재정의한다.

08 · 2–3H COMPUTE PLAN

Frozen predictive filter는 한 GPU로 반복하고, cross-dataset과 LoRA만 선택적으로 병렬화한다.

H100 SXM 80GB, BF16, cached V-JEPA 2/2.1 chunk latents를 기준으로 한 초기 scheduler budget이다. A100 80GB는 H100 수의 약 1.7배 또는 1.5–2배 wall-clock을 초기값으로 둔다. 한 run은 full official split의 한 configuration·한 seed이며 LoRA 단계만 raw video encoder를 다시 실행한다.

RUN DEFINITION

EK100의 filter·objective·correction 분석은 동일 feature cache를 공유한다. 세 seed를 2–3시간 안에 끝내려면 각각 독립 GPU job으로 동시에 실행한다. Ego4D transfer와 end-to-end LoRA는 별도 heavy run으로 분리해 core ablation의 iteration 속도를 유지한다.

CALIBRATE BEFORE LAUNCH

첫 full experiment 전에 throughput만 측정해 allocation을 확정한다.

5% calibration은 dataloader·forward·backward·evaluation 시간을 분리하는 engineering run이다. H100/A100 latency는 별도 표로 보고 확정된 GPU 수로 전체 official split을 실행한다.

G_A100,initial ≈ ceil(1.7 × G_H100)
