RESEARCH BRIEF · LITERATURE SWEEP THROUGH 2026-08-09

One Video, Any Budget

목표는 token 수만 줄이는 compressor가 아니다. 영상의 미래를 이해하는 데 충분한 상태를 만들고, budget이 허용하는 만큼만 encoder 계산과 표현을 점진적으로 확장하는 video encoder다.

핵심 thesis

영상이 요구하는 token 수는 pixel complexity가 아니라 아직 해소되지 않은 predictive uncertainty로 결정되어야 한다.

01 · RESEARCH VERDICT

셋 다 가능하다. 대신 세 논문이 답할 질문을 섞지 않는다.

VideoFlexTok은 이미 time-causal encoder, nested dropout, DINOv2 REPA, streaming tokenization을 generation 축에서 제시했다. Query-aware hierarchy와 latent video reasoning에도 2025–2026년의 강한 경쟁작이 있다. 그렇다고 세 아이디어가 불가능한 것은 아니다. 각각의 novelty와 결정적 실험을 아래처럼 분리하면 독립된 논문 질문이 된다.

Predictive rate–distortion

write 시점에는 질문을 보지 않고 상태를 만든다. 이후 unseen understanding query와 streaming memory에서 표현의 재사용성을 검증한다.

NO-SCRATCH RECIPE

현실적인 학습 순서

  1. V-JEPA 2를 frozen teacher로 두고 pretrained video ViT student를 초기화한다.
  2. register/proxy tokens, causal adapters, predictor, budget router만 먼저 학습한다.
  3. 가능성이 확인되면 student 마지막 block과 LoRA를 점진적으로 연다.
  4. LLM 연결은 encoder 가설이 검증된 뒤 projector/SFT 단계로 분리한다.

FOUR FALSIFIABLE HYPOTHESES

논문이 반드시 증명해야 할 것

  1. 한 모델의 모든 budget이 budget별 전용 모델에 근접한다.
  2. predictive objective가 DINO/reconstruction보다 temporal reasoning을 잘 보존한다.
  3. in-encoder routing이 post-hoc pruning보다 실제 TTFT와 GFLOPs를 줄인다.
  4. router가 oracle budget과의 간격을 의미 있게 좁힌다.

03 · THREE TOPICS, REBUILT

각 아이디어를 논문 단위로 구체화하면

탭을 눌러 각 안의 실제 novelty, 학습 방식, 결정적 실험과 중단 기준을 비교할 수 있다.

TOPIC 01 · PRIMARY

Temporal reasoning을 보존하는 실제 dynamic encoder

VideoFlexTok의 “generation을 understanding으로 바꾼다”만으로는 약하다. time-causal과 streaming도 이미 들어 있다. novelty는 future-semantic sufficiency + internal conditional compute다.

Method

  • 시점별 gist register를 shallow block에서 생성
  • predictive residual이 큰 event/region만 deeper block으로 전달
  • 각 depth의 residual token을 합치면 nested representation 형성
  • V-JEPA 2 teacher의 현재 및 미래 latent를 여러 horizon에서 distill
  • budget-conditioned stochastic training으로 하나의 weight 유지

Decisive experiment

같은 output token 수와 같은 encoder GFLOPs에서 reconstruction/DINO teacher 대비 TempCompass의 direction·order, Something-Something v2, action anticipation을 동시에 개선해야 한다.

Kill criterion

frozen proxy가 full V-JEPA feature의 temporal score를 보존하지 못하거나, routing overhead를 포함한 latency가 fixed encoder 대비 줄지 않으면 구조를 축소한다.

TOPIC 02 · MULTI-QUERY AMORTIZATION

한 번 encode하고, 여러 질문이 같은 tree와 열린 가지를 재사용한다

VideoTree는 query를 보며 tree를 만들고, QTS+/VideoRouter는 flat dense tokens에서 query-relevant evidence를 고른다. 원안의 핵심은 처음부터 query-agnostic hierarchy의 multi-query amortization이다. tree뿐 아니라 이전 질문이 이미 펼친 branch도 다음 질문이 공유한다.

Method

  • scene/event boundary에 맞춘 temporal latent tree를 query 없이 생성
  • parent token은 summary, child token은 parent가 잃은 predictive residual로 학습
  • query router가 top-down beam으로 branch와 depth를 budget 안에서 결정
  • global gist를 항상 남겨 잘못된 early routing의 복구 경로 제공
  • 펼친 branch를 cumulative cache에 남기고 후속 query에서는 추가 evidence만 연다
  • 동일 영상은 다시 encode하지 않고 query 수에 따른 total cost를 직접 평가

Decisive experiment

같은 영상에 Q=1·5·10·20개의 질문이 순차적으로 들어올 때, VideoTree/QTS+/flat top-k보다 cumulative encoder+routing+LLM cost와 accuracy의 Pareto frontier가 좋아야 한다. Q가 늘수록 평균 query 비용이 내려가는 곡선이 이 논문의 결정적 그림이다.

Kill criterion

Q가 늘어도 average cost가 줄지 않거나, 동일 cumulative compute에서 flat cache/top-k보다 정확도가 낮으면 multi-query amortization claim은 성립하지 않는다.

TOPIC 03 · HIGH RISK, HIGH REWARD

Memory에 저장하는 것이 아니라, visual latent 안에서 계속 생각한다

VideoLatent와 DyLaR도 video QA를 latent space에서 푼다. 따라서 continuous think token만으로는 부족하다. 차별점은 query 전부터 유지되는 streaming causal world-state가 recurrent computation으로 미래를 예측하고 belief를 수정하며, 필요한 만큼 reasoning step을 늘리는 데 있다.

Streaming observation Zₜ
k=0Mₜ⁽⁰⁾observe
→
k=1Mₜ⁽¹⁾predict
→
k=2Mₜ⁽²⁾compare + revise
→
k=KMₜ⁽ᴷ⁾answer / carry
future latent prediction ↺ new evidence · revise belief · halt by uncertainty
Memory granularityGist ⊂ Event ⊂ Object-state
Reasoning depth1 step ⊂ 2 steps ⊂ K steps

Method

  • stream을 한 번만 보며 bounded causal visual state Mₜ를 유지
  • recurrent operator Mₜ⁽ᵏ⁺¹⁾ = R(Mₜ⁽ᵏ⁾, Zₜ, q?)로 latent thought를 전개
  • 각 step이 future teacher latent를 예측하고 새 관측과의 오차로 belief를 수정
  • query가 없을 때는 world-state를 갱신하고, query가 오면 필요한 extra rollout만 수행
  • uncertainty 기반 halting으로 쉬운 장면은 일찍 멈추고 어려운 장면은 더 생각
  • memory granularity와 recurrent reasoning depth를 동시에 Matryoshka로 학습

Decisive experiment

동일 FLOPs에서 더 깊은 feed-forward encoder, 더 많은 memory token, prediction-only/no-recurrence, textual CoT, fixed-step recurrence와 비교한다. latent step을 늘릴수록 temporal order·causality·state change·anticipation·counterfactual 정확도가 체계적으로 올라가야 한다.

Kill criterion

같은 compute의 추가 encoder depth보다 recurrence가 낫지 않거나, reasoning step을 늘려도 어려운 temporal question의 정확도가 오르지 않으면 이것은 latent reasoning이 아니라 반복 계산일 뿐이다.

FIRST GPU PILOT · 2026-08-09

단순 shared recurrent head는 K=0→4에서 30.4→31.3%로 단조 증가하지 않았고 no-loop 32.2%를 넘지 못했다. 현재 구조는 no-go이며 explicit predictive residual + contradiction target으로 좁혀 다시 검증한다.

04 · NOVELTY BOUNDARY

VideoFlexTok과 무엇이 정확히 다른가

축VideoFlexTok제안하는 flagship검증 포인트
Primary goal generation용 flexible tokenizer understanding용 anytime encoder temporal reasoning / anticipation
Training signal flow reconstruction + DINOv2 REPA multi-horizon V-JEPA latent prediction predictive sufficiency at every prefix
Budget structure tail prefix over per-frame registers gist + learned event/region residuals non-linear, content-adaptive refinement
Encoder compute token output length 중심 active tokens와 depth를 함께 조절 encoder GFLOPs / latency 포함
Streaming sliding-window encode, decoded-frame conditioning causal latent state 자체를 계속 갱신 bounded state, unknown future query

time-causal attention과 “streaming 가능” 자체는 novelty로 주장하지 않는다. 두 요소는 VideoFlexTok이 이미 명시적으로 보여준다.

THE OPEN SPACE

세 논문이 점유할 서로 다른 공간

01 · Anytime: predictive semantics와 encoder 내부 conditional compute를 하나의 nested representation으로 묶는다.

02 · Multi-query: query-agnostic tree와 cumulative branch cache로 질문 수가 늘수록 평균 비용을 낮춘다.

03 · Latent reasoning: query 전 streaming world-state와 adaptive recurrent belief revision을 이중 Matryoshka budget으로 만든다.

BOTTOM LINE

하나의 backbone, 세 개의 독립 질문.

셋 다 논문이 될 수 있다. 1번은 얼마나 적게 encode할 수 있는가, 2번은 한 번 encode한 영상을 몇 개의 query가 얼마나 싸게 공유하는가, 3번은 visual latent가 더 오래 생각할수록 실제 temporal reasoning이 좋아지는가를 묻는다. 구현 자산은 공유하되 contribution과 성공 기준은 합치지 않는다.
