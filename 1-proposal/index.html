PROPOSAL 01 · BROAD REPRESENTATION PROBLEM

State–Innovation Anytime Video Encoder

image의 coarse-to-fine을 그대로 복사하지 않는다. video를 계속 유지되는 semantic state와 새로 발생한 semantic innovation으로 나누고, 모든 budget이 두 역할을 함께 보존하는 nested representation을 학습한다.

PRIMARY AXISRepresentation
QUERY AT ENCODEUnavailable
MAIN METRICAccuracy / encoder FLOPs
ONE-SENTENCE CLAIM

각 추가 token group을 작은 budget이 아직 설명하지 못한 state와 innovation residual에 정렬하면, 하나의 pretrained encoder가 임의의 token·depth budget에서도 temporal understanding을 보존할 수 있다.

01 · THE PROBLEM

Video에서 “coarse”가 무엇인지 정의하지 않으면 첫 token의 역할도 알 수 없다.

image에서는 layout→object→texture가 자연스러운 해상도 축이다. 그러나 video에서 coarse token이 평균 frame인지, 주행동인지, motion인지, 긴 시간의 요약인지는 서로 다른 주장이다. 먼저 기존 token의 실제 역할을 측정하고, 시간축에 고유한 state–innovation 분해를 학습 목표로 준다.

FAILURE SCENE

64초 중 0.5초의 상태 변화가 질문의 정답을 바꾼다.

appearance는 거의 같지만 컵이 비워지는 순간, 손의 방향 전환, 행동 순서 반전은 temporal QA에 결정적이다.

L1

Pixel fidelity ≠ answer sufficiency

texture를 잘 복원해도 state change와 causal order를 잃을 수 있다.

L2

질문을 미리 사용할 수 없다

query-aware selector와 달리 encoder는 미래의 다양한 downstream task에 재사용되어야 한다.

L3

Post-hoc pruning은 encoder를 싸게 만들지 않는다

dense ViT를 전부 실행한 뒤 token만 줄이면 LLM prefill은 줄지만 vision FLOPs는 그대로다.

L4

앞 token이라고 자동으로 “coarse”해지지 않는다

nested dropout은 prefix validity를 유도하지만, 각 token이 state·motion·order·rare event 중 무엇을 담당하는지 보장하지 않는다.

THE OPEN GAP

“Not coarse-to-fine, but persistence ↔ innovation.” Pixel residual이 아닌 semantic persistence와 innovation을 role-paired nested tokens로 만들고, 각 추가 group의 marginal information을 직접 감독하는 anytime video encoder가 핵심 빈틈이다.

03 · VIDEO-NATIVE TOKEN ROLES

Coarse-to-fine 대신 persistence ↔ innovation을 검증 가능한 대칭 역할로 둔다.

상태와 변화는 반대 역할이지만 둘 다 작은 budget에서 필요하다. 따라서 state-only prefix 뒤에 motion token을 붙이지 않고, 각 budget tier마다 state와 innovation token을 짝으로 추가한다.

M1

Role-paired registers

k번째 group은 Sₜ와 Iₜ 전체를 반복하지 않고 budget k−1의 reconstruction residual만 설명한다. router는 residual norm을 예측해 실행 depth를 정한다.

IS V-JEPA REQUIRED?

No. V-JEPA는 temporal predictive semantics가 강해 primary teacher로 합리적일 뿐 method의 정의가 아니다. Multi-horizon future prediction도 optional auxiliary loss다. 최소 두 종류의 teacher와 EMA self-teacher에서 같은 ordering이 재현되어야 teacher-specific trick이 아닌 일반 objective로 주장할 수 있다.

05 · NO-SCRATCH RECIPE

먼저 token role을 진단하고, objective가 필요하다는 사실부터 증명한다.

PHASE A · AUDIT

What is the first token?

VideoFlexTok·M3-style nested tokens와 uniform pooling을 full official splits에서 intervention probe로 분석한다.

PHASE B · OBJECTIVE

Frozen semantic targets

cached dense features 위에서 direct REPA, same-target MRL, relation alignment, 제안 loss를 동일 proxy로 비교한다.

PHASE C · COMPUTE

Adapters + gates

효과가 확인되면 causal adapter, role registers, stage gate를 열어 token 수와 실제 encoder depth를 함께 줄인다.

PHASE D · TRANSFER

Teacher and task transfer

두 teacher·두 video datasets·frozen downstream probes에서 role ordering과 Pareto gain이 재현되는지 확인한다.

07 · KILL TESTS

아래 셋 중 하나가 실패하면 role-aware claim을 즉시 줄인다.

NO-GO 01

기존 token도 이미 같은 role을 가진다

VideoFlexTok·MRL prefix가 intervention probe에서 안정적인 state–innovation ordering을 이미 보이면 analysis novelty와 explicit role loss를 축소한다.

NO-GO 02

V-JEPA에서만 작동한다

VideoMAE 계열 또는 EMA teacher에서 ordering과 Pareto gain이 재현되지 않으면 general objective가 아닌 V-JEPA distillation으로 claim을 줄인다.

NO-GO 03

Role은 예쁘지만 성능에 필요 없다

같은 token·FLOPs의 direct REPA와 temporal benchmark 차이가 없으면 해석 가능한 분석 결과만 남기고 encoder SOTA claim을 폐기한다.

08 · 2–3H COMPUTE PLAN

한 configuration을 2–3시간에 끝내려면 proxy는 가볍게, encoder adaptation은 강하게 병렬화해야 한다.

아래는 H100 SXM 80GB, BF16, optimized attention, pre-sharded dataloader를 가정한 초기 scheduler budget이다. A100 80GB만 가능하면 H100 수의 약 1.7배 또는 1.5–2배 wall-clock을 먼저 계획한다. 한 run은 full official split의 한 configuration·한 seed이며 queue 대기시간은 제외한다.

RUN DEFINITION

논문 결과는 최소 3 seeds다. seed를 독립 Slurm job으로 동시에 배치하고 one-time multi-teacher cache는 모든 objective·budget·baseline이 공유한다. 아래 수치는 ±30% planning range이며 5% throughput calibration 후 H100/A100 allocation을 확정한다.
